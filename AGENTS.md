# AutoClip quality and release requirements

Read [docs/TESTING_ACCEPTANCE.md](docs/TESTING_ACCEPTANCE.md) before changing code or preparing a release. Use [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md) for release operations.

- Diagnose the latest report using its version, platform and build. Preserve unrelated work, user data and secrets. Use isolated data directories for every test.
- For a production defect, reproduce the triggering conditions and show the regression fails before the fix and passes afterward. Test boundaries between configuration, requests, persistence, runtime and UI; test count alone is not acceptance.
- Run `python scripts/quality_gate.py --report /absolute/local/path/quality.json` before claiming a candidate passes source checks. Install dependencies first. The report identifies the commit and tracked changes. A targeted run is useful during development; a release requires all groups and the exact tag's CI.
- Python correctness lint, frontend lint/types/tests/build, backend tests, version/readme contracts and release-gate regressions are blocking. Existing general Python style warnings remain debt; never waive new runtime errors. Add corresponding checks when changing provider routing, migrations, retries, SQLite, optional runtimes, downloads or telemetry.
- Keep all eight UI locales consistent. Change the event producer, query/measurement contract and validation acceptance together.
- Before creating any release tag, build the untagged candidate branch with Desktop Build, complete every required installed-package case on both platforms and every repair regression, and pass Internal Acceptance. Bind evidence to the exact source SHA and package hashes. The receipt always identifies the current source and packages. After a source/version/package change, rebuild when necessary and re-run affected assertions; previously passed unaffected assertions may be inherited only through the audited impact-inheritance contract in docs/TESTING_ACCEPTANCE.md, preserving their original source, package hashes and execution time. Pending, failed or unknown assertions cannot be inherited. Do not consume a public version for internal repairs. An authorized annotated tag must carry `Internal-Acceptance-Run: RUN_ID`; the tag build rejects missing, failed or mismatched acceptance.
- Use the final installed package on Windows x64 and macOS arm64 for the required acceptance cases. Record OS, VM/emulation status, portable runtime, package SHA-256, source commit and outcomes. A source checkout, loopback model fixture, wheel test or successful CI does not replace desktop UI/real-model acceptance.
- A candidate with pending/failed/skipped required cases, unresolved blockers, no observation samples or mismatched evidence is **NO-GO**. Do not bypass this by extending an observation period or merely disclosing the gap. Fix and re-test first.
- `scripts/release_acceptance.py` and the **Release Acceptance** workflow must pass before **Promote / Halt Release**. Never promote directly with `gh release edit`, change an existing tag, claim a local fix is shipped, or close an issue before release and report-specific verification.
- Hotfixes start from the affected tag and contain only necessary repairs and regression tests. Keep unrelated quality cleanup and new features separate; bring the fixes back to main.
- Paid calls, contacting testers, publishing, release promotion and rollback need authorization from the user's request/session. Prepare concrete evidence before asking for any missing authorization. Never upload raw PostHog/Sentry exports, credentials, personal paths or user media to the public repository; only reviewed sanitized acceptance summaries belong there.

## Local-first derivative scope (2026-11-25)

- The current selection and page contract is [whole-transcript selection](docs/local-first/WHOLE_TRANSCRIPT_SELECTION.md): read all source cue cores, synthesize an ordered full-scope brief, screen original passages with grounded evidence, rank before measuring candidate audio, review the cleaned body and separately review any moved hook. A complete, independently reviewed source-order candidate may be presented **as source order**, not mislabeled hook-first. Keep old v1 reports distinguishable. The landing page lists candidates; an individual candidate opens its own local detail URL. Never load private report text, transcripts, original frames or clips into Codex/CUA for quality inspection.

- Read `docs/local-first/TECHNICAL_AUDIT_2026-11-25.md` and `GITHUB_SYNC_STATUS.md` before continuing this branch. The pinned baseline is `2f511907a72cbfbb8d86639f6441967b826acb6a`; keep upstream copyright and license notices. This is a derivative fork, not an original replacement project.
- Approved A/B/chardet/FFmpeg artifacts remain prepared; do not reinstall/re-request them or add downloads silently. A runnable macOS local-caption development workspace now exists: `scripts/local_captions_control.py` and `backend/local_captions_*`, default loopback port 19784. Subtitle scope: `docs/local-first/LOCAL_CAPTIONS_WORKSPACE_2026-11-25.md`. New smart reassembly scope: `docs/local-first/SMART_REASSEMBLY_2026-11-26.md`. Updated editorial order and review boundaries: `docs/local-first/EDITORIAL_RECUT_2026-11-26.md`. Lock a cleaned source-order body before choosing a retained hook; separately review the exact resulting edit. It reuses the original Whisper, Draft/Scene, caption pagination/timeline and Studio renderer; captioned preview/export default on, editable text with original timestamps/revision history, explicit hash-bound export approval, MP4/SRT/JSON, cancel/retry. All 13 current language dictionaries have the same local-caption keyset. The local smart-recut panel proposes source-cue-grounded topics, highlight-first cuts, removable filler and measured long-pause trims. It does not certify meaning or predict views, replace the full original/Tauri UI, or offer live microphone dictation or word-level karaoke. The verified local model has a private exact Unix socket in its own sandbox; never expand it to TCP, a configurable remote provider, or a cloud fallback. Sentence precision, real-material output quality, full-app network observation/physical offline tests and full source/package acceptance remain pending; no real material has been exported without review. Only self-generated media may be opened in CUA/Codex; user source/transcripts/plans stay local. The user workspace may intentionally remain running for their use; stop only its verified owned PIDs with the control script. Never remove sandbox restrictions to work around macOS refusing nested sandbox_apply: a separately started offline broker is required. Keep the legacy cloud-capable application entry disabled for private-media testing.
- Default workflow: local file → local ASR → verified on-device model → editable plan → explicit approval of that exact revision → local render/export. Preserve input hashes and originals. No remote transcription, LLM, image generation, media analysis, publishing, diagnostics uploads, telemetry, remote fonts, template hot updates, or silent cloud fallback in this profile.
- A provider name, private/LAN IP, `.local` hostname or loopback URL alone is not proof that inference stays on this computer. Verify the endpoint and the model process; enforce outbound restrictions for the application and all its children/model services. Never read or reuse Codex, ChatGPT, browser or other application credentials.
- Downloads require prior user confirmation covering source, size, license, purpose and network behavior. The proposal is not approval. Unknown/changed sources, unresolved licenses or additional large components require another decision; do not execute upstream install scripts or mirror fallbacks blindly.
- Reuse Studio's `Draft.scenes`, editor, renderer and subtitle mapping. Add grounded content strategies and a final-plan approval boundary; do not claim reassembly merely by changing a title or prompt. Local ASR timestamps still need measured accuracy; subtitle labels are not reliable speaker diarization.
- Keep all user media, transcript text, plans containing real content, weights, databases, caches, command logs and raw test evidence under ignored local directories. Public commits may contain reviewed source, synthetic fixtures and sanitized development documentation only. A fork inherits public upstream assets/history; do not add private data or claim the inherited history has been exhaustively audited.
- UI work uses top navigation, compact paste/drop/“＋” input and a visible top-right round “×” on dialogs, with Esc, focus handling and unsaved-change protections. Preserve complete original brand assets and adapt transparency/readability to the actual background.
- Follow `docs/local-first/IMPLEMENTATION_AND_ACCEPTANCE.md` stage gates. Real export, three non-contiguous ranges, source hash preservation, network isolation, recovery and human viewing remain pending until actually tested. Source quality gate, desktop/package acceptance and local-only acceptance are separate records.
- Synchronize reviewed batches to the verified personal fork on a `codex/` branch, never to upstream or a release tag. Check remote rules and deployment triggers first; preserve other work. Keep `GITHUB_SYNC_STATUS.md` accurate and verify the remote commit after pushing. Code synchronization is not a media/data/system backup.
